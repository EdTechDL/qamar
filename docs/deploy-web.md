# Deploying the web app (Cloudflare Pages)

The web target is a PWA: an installable, offline-capable SPA. This document
covers how it's built, how to deploy it, and the parts that are hand-rolled
because Expo doesn't provide them.

## Build

```bash
npm run build:web
```

That runs two steps:

1. `expo export --platform web --output-dir dist` — Metro bundles the app and
   copies `public/` to the export root.
2. `node scripts/build-sw.mjs` — rewrites `dist/sw.js`, replacing the
   `__BUILD_ID__` and `__PRECACHE__` placeholders with a content hash and the
   real list of exported files.

Step 2 is not optional. Metro content-hashes the bundle and font filenames, so
the precache list cannot be written ahead of time. Deploying `public/sw.js`
unprocessed would register a worker that tries to cache a literal
`__PRECACHE__` and fails its install.

Preview the built output locally, with SPA fallback matching production:

```bash
npm run serve:web
```

## Deploy

### Git integration (recommended)

Connect the repo once in the Cloudflare dashboard → Workers & Pages → Create →
Pages → Connect to Git, then:

| Setting | Value |
| --- | --- |
| Build command | `npm run build:web` |
| Build output directory | `dist` |
| Node version | picked up from `.node-version` |

Every push to `main` redeploys. No API tokens or repo secrets involved, which
is why this is preferred over a GitHub Actions workflow.

### Direct upload

```bash
npm run build:web && npx wrangler pages deploy dist --project-name qamar
```

## Repo files that exist only for this

| File | Purpose |
| --- | --- |
| `public/index.html` | The document shell. See "Template substitution" below. |
| `public/manifest.webmanifest` | PWA manifest — Expo generates none. |
| `public/sw.js` | Service worker source, with placeholders. |
| `public/_redirects` | Cloudflare SPA fallback: `/* /index.html 200`. |
| `public/_headers` | Immutable caching for hashed assets, `no-cache` for `sw.js`. |
| `public/icon-*.png` | Generated by `npm run icons`. |
| `scripts/build-sw.mjs` | Injects the precache manifest. |
| `scripts/generate-icons.mjs` | Draws the icon set (no image dependencies). |
| `.npmrc` | `legacy-peer-deps=true`, or the Cloudflare install fails. |
| `.node-version` | Pins the build image's Node. |

## Template substitution

With `web.output: "single"`, Expo reads `public/index.html` as the document
template and falls back to its own if absent. **`app/+html.tsx` has no effect
in this mode** — it only applies to `static` and `server` output.

The CLI rewrites the template with naive first-occurrence `String.replace`:

- `%LANG_ISO_CODE%` ← `expo.web.lang`
- `%WEB_TITLE%` ← `expo.name`
- before `</head>` ← `theme-color` and `description` meta, from `expo.web.*`
- before `</body>` ← the bundle `<script>`

Because each replacement takes the *first* match, none of those four tokens may
appear earlier in the file than its intended position — not even inside an HTML
comment. Doing so injects the bundle script into your comment and leaves the
real placeholders unsubstituted, which fails silently.

Do not declare `theme-color` or `description` in the template; they come from
`app.json` and would be duplicated.

## Caching model

`sw.js` uses three strategies:

- **Navigations** → the precached `/index.html` shell, so deep links like
  `/surahs/2` resolve offline and expo-router routes client-side.
- **Same-origin assets** → stale-while-revalidate against a versioned
  `qamar-shell-<buildId>` cache. A new build id creates a new cache and the old
  one is deleted on activate.
- **Audio** → cache-first into a separate, unversioned `qamar-audio-v1` cache,
  capped at 800 entries with FIFO eviction. The qari source sends no CORS
  headers, so these are opaque responses; they're cached anyway, since an
  opaque response still replays through `<audio>`.

The `install` handler uses `cache.addAll`, which is atomic — one 404 aborts the
install and the previous worker stays active. A broken deploy fails closed.

## Font imports

Import each weight from its own subpath:

```ts
import { Inter_400Regular } from '@expo-google-fonts/inter/400Regular';
```

Never from the package root. The barrels re-export all 26 faces, and Metro
can't tree-shake a `require()` of a binary asset — importing from the root cost
8.4 MB of unused TTFs in the export.

## Known gaps

- Audio is only cached after first playback; there's no "download this surah
  for offline" path on web (SPEC §12.4 covers the native one).
- The recitation source is still the unresolved D3 placeholder (issue #3). A
  public deploy serves those URLs to real visitors.
- No offline indicator in the UI. Cached audio replays silently; uncached audio
  simply fails.
